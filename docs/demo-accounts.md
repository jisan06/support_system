> [!IMPORTANT]
> **REMINDER — SEEDING REQUIRED**:  
> Demo accounts are only created and available **after running `php artisan db:seed`** (or `php artisan migrate --seed`).  
> If you only executed `php artisan migrate`, these user records do not exist yet in your database and login will fail.

> [!CAUTION]
> **DEVELOPMENT & DEMO CREDENTIALS ONLY**:  
> The credentials documented below are generated by the default database seeder (`UsersTableSeeder.php`).  
> **Never use these credentials in a public or production environment.** Change or remove these accounts and their passwords before deploying the system to production.

## Pre-Configured Demo Accounts

After running `php artisan db:seed` (or `php artisan migrate --seed`), the database is populated with three default accounts demonstrating the different access tiers and roles:

### 1. System Administrator (Super Admin)

- **Email**: `super_admin@gmail.com`
- **Password**: `12345678`
- **Account Type**: `admin`
- **Assigned Role**: `Super Admin` (Level 1, all permissions)
- **Primary Dashboard**: `/admin`

#### What This Account Demonstrates:
- Complete administrative control over the entire system.
- Creation and management of dynamic Roles, Permission slugs, and User assignments.
- Global Ticket Desk: view all customer tickets, assign/reassign tickets, override priority/status, and view all audit logs.
- SLA & Business Hours Configuration (`/admin/settings/sla`): customize business timezone, working days, daily hours, target minutes, and escalation actions.
- CSV Ticket Batch Import (`/admin/tickets/import`): upload CSV files to batch-create tickets with background tracking and error reports.
- System health monitoring, database backup management, and notification settings.

---

### 2. Support Agent

- **Email**: `agent1@gmail.com`
- **Password**: `Js@12345`
- **Account Type**: `admin`
- **Assigned Role**: `Support Agent` (Dynamic Role, Level 4)
- **Granted Permissions**:
  - `view_ticket`: Access ticket desk and read ticket conversations
  - `edit_ticket`: Update ticket status and priority
  - `reply_ticket`: Post public replies to customers
  - `internal_note_ticket`: Post confidential, internal-only notes
  - `receive_ticket_assignments`: Eligible for manual and automatic ticket assignment
  - `view_customer`: View customer profiles associated with tickets
- **Primary Dashboard**: `/admin`

#### What This Account Demonstrates:
- Day-to-day support agent workflows under dynamic RBAC boundaries.
- **Workload Assignment**: Receives automatic assignments via the Least Active Workload strategy.
- **Two-Way Communication**: Replying to customer inquiries and monitoring real-time SLA countdowns.
- **Confidential Internal Collaboration**: Posting private internal notes and reviewing internal note history without exposing sensitive details to customers.
- **Permission Restrictions**: Cannot access system administration areas (e.g., Roles, System Settings, Backups, or User Management).

---

### 3. End Customer

- **Email**: `hasan@gmail.com`
- **Password**: `Js@12345`
- **Account Type**: `customer`
- **Assigned Role**: None (Direct Customer Portal Access)
- **Primary Dashboard**: `/customer/dashboard`

#### What This Account Demonstrates:
- **Dedicated Customer Workspace**: Modern, focused customer self-service portal (`/customer`).
- **Ticket Submission**: Create new tickets, select categories, choose urgency priorities, and upload attachments.
- **Live SLA Tracking**: View real-time SLA target guarantees ("Within 1–2 Hours", "On Track", "Due Date").
- **Conversation Stream**: Reply directly to staff messages, view uploaded attachments, and track issue progress.
- **Strict Privacy Isolation**: Internal notes, staff-only communications, and internal audit histories are strictly hidden.
- **Reopening Resolved Tickets**: Reopen resolved issues with explanation comments.
- **Cross-Tenant Security**: Customers can only see and access their own tickets and notifications; accessing another customer's ticket returns an authorized `403 Forbidden`.
